# Spreadsheet intent and proportional complexity

Treat spreadsheets as practical information tools, not automatically as analytics products. Determine what the user wants to record, calculate, organise or report. Match complexity to the request.

- Lists/registers: clean headers, filters if helpful, readable widths and straightforward data entry.
- Inventory: item, quantity, location and other justified fields; do not fabricate stock data.
- Budgets: simple income, expense and total formulas when appropriate; avoid speculative forecasts.
- Trackers: task, owner, due date and status if relevant; no mandatory dashboard.
- Campaign results: only metrics supported by supplied or authorised data; clearly label calculated fields.
- Advanced analytics: add pivots, charts, forecasts, KPIs, scenarios or dashboards only when requested or clearly necessary for the user's stated purpose.

Do not add artificial sample records as if they were real. If examples are useful, mark them clearly as examples. Do not invent formulas requiring unknown inputs. Use formulas only when they add practical value; preserve user-provided values and column names.

Formatting should improve usability: readable headers, consistent date/currency formats, frozen header where helpful, sensible column widths, accessible contrast and minimal decoration. Avoid excessive sheets, complex dependencies, hidden logic or fragile formulas.

For print-bound spreadsheets, apply the page-aware document rules: paper size, landscape as needed, fit-to-width without microscopic text, repeating headers and sensible page breaks.

Ask a clarifying question only if a missing detail materially blocks the workbook's useful structure. Do not require the user to specify analytics sophistication.
